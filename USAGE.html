svelte-layout-kit

A collection of ready-to-use, fully-customisable landing page layouts for SvelteKit apps. Drop in a component, pass your props, done.

Installation

1
Install the package

Install from npm or link the local package:

terminal 
# npm (once published)
npm install @aryagg/svelte-layout-kit

# or link a local sibling folder
npm install ../svelte-layout-kit

Your package.json dependency entry:

package.json 
{
  "dependencies": {
    "@aryagg/svelte-layout-kit": "^0.0.1"
  }
}
2
Verify peer dependencies

The package requires svelte ^5.0.0 as a peer dependency — already satisfied by any SvelteKit 2+ project using Svelte 5.

Tailwind CSS Setup

⚠️

Required step. Tailwind v4 excludes node_modules from scanning by default. Without this fix, responsive classes like sm:w-8/12 from the package will be missing in your build.

Add a @source directive to your global CSS file (the one that imports Tailwind). The path must be relative to that CSS file.

src/lib/styles/index.css 
/* ① Import Tailwind (v4 syntax) */
@import "tailwindcss";
@config "./tailwind.config.ts";

/* ② Opt the package into Tailwind's scanner
   — node_modules is excluded by default in v4, @source bypasses that */
@source "../../../node_modules/@aryagg/svelte-layout-kit/dist";
💡

Adjust the relative path if your CSS file is in a different location. Count the folder levels up from your CSS file to the project root, then append node_modules/@aryagg/svelte-layout-kit/dist.

The dist/ folder is what ships with the package and contains the pre-compiled .svelte files Tailwind needs to extract class names from.

ℹ️

The components use your app's Tailwind theme tokens such as text-accent, bg-surface-secondary, btn-primary, etc. Make sure those CSS variables are defined in your theme before rendering the components.

Importing Components

All three landing page components are exported from the package root. Import only what you need:

+page.svelte 
import { LandingPage1, LandingPage2, LandingPage3 } from '@aryagg/svelte-layout-kit';

Theming

The components consume CSS custom properties from your app's theme. These must be defined in your global CSS (typically via your Tailwind theme config):

CSS VariableUsed for
--semantic-accentHighlighted words, accent buttons, greeting colour
--surface-secondaryLandingPage3 background fill
.btn-primaryPrimary CTA and search buttons
.btn-secondarySecondary action button (LandingPage3 Resume)
ℹ️

These variables are already defined if you scaffolded your app from the sooper-dooper-app skeleton. No extra work needed.

Full Page Example

A complete SvelteKit page that lets users switch between all three layouts with a mode toggle — exactly as used in /test:

src/routes/test/+page.svelte 
<script lang="ts">
  import { LandingPage1, LandingPage2, LandingPage3 } from '@aryagg/svelte-layout-kit';
  import Topbar from '$components/core/Topbar.svelte';

  let active = $state<1 | 2 | 3>(1);
  let mode   = $state<'default' | 'props'>('props');
</script>

<div class="flex h-screen flex-col overflow-hidden">

  <!-- App topbar -->
  <Topbar />

  <!-- Layout switcher -->
  <div class="flex gap-2 border-b p-3">
    <button onclick={() => active = 1} class="btn btn-sm btn-ghost">Product</button>
    <button onclick={() => active = 2} class="btn btn-sm btn-ghost">Real Estate</button>
    <button onclick={() => active = 3} class="btn btn-sm btn-ghost">Portfolio</button>
  </div>

  <!-- Preview -->
  <div class="flex-1 overflow-y-auto">
    {#if active === 1}
      <LandingPage1 title="Nordic Home" ctaText="Shop Now" />
    {:else if active === 2}
      <LandingPage2 title="Find Your Perfect Home" />
    {:else}
      <LandingPage3 greeting="Hello, I'm Arya" role="Frontend Developer" />
    {/if}
  </div>

</div>
